# Local implementation pilot — 2026-10-17

Status: bounded prototype evaluation, not a production benchmark. Single host, one execution of the PostgreSQL scenario; no confidence interval or production workload.

Environment: Linux 6.18 amd64; 13th Gen Intel Core i7-13700H; Go `go1.27.1-X:nodwarf5`; PostgreSQL 18.6, with the temporary cluster started using `fsync=on` and `synchronous_commit=on`. Original ring commit `0afd02a680608511ab1f66dbe854a1d1152c001a`; `ring/ring.go` SHA-256 `3bf573df680d806efe3ffbe3b02666519f82866a096cd757290f19132cdc867d`.

Reproduce with `make test-db` and `make bench` from `generation-fenced-shard-transfer/`. The database target creates a fresh temporary cluster and removes it after the run. Its deterministic unsafe baseline printed:

```text
entity=entity-28 partition=0 before=A value=acknowledged-value candidate=B immediate_read=missing
```

The integration tests passed an A → B → A stop-and-copy handoff, recreating the coordinator between durable phases. They checked stale source rejection, a repeated target copy, deduplication after migration, a versioned deletion, return migration, rollback, denial of direct table DML to `whm_app`, and pool retirement with in-flight leases. These checks do not establish safety under all schedules.

Raw local lookup samples (`ns/op`, five benchmark invocations, mixed set of 4,096 keys):

All cases reported `0 B/op`, `0 allocs/op`. These are in-process lookups, not database operation latency. The effective-owner benchmark does not perform a ring lookup, database check, or migration. Benchmark source and flags: `go test ./internal/placement -run '^$' -bench BenchmarkLookup -benchmem -count=5` and `go test ./internal/ownership -run '^$' -bench BenchmarkPartitionRoute -benchmem -count=5`.
